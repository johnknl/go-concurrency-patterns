# Go Concurrency Patterns

The recurring arrangements of goroutines, channels, `context`, and `sync`, named and described like design
patterns, with anti-patterns for the common mistakes. Each pattern is a small, tested package in plain Go; the
documentation shows its code straight from the source.

Documentation: <https://johnknl.github.io/go-concurrency-patterns/>, starting with the
[principles](docs/index.md#principles) and the [catalog](docs/catalog/index.md).

## Example

A fan-out/fan-in with a `sync.WaitGroup`:

<!-- code: patterns/fanout#Example_workers:main -->
```go
func main() {
	in := emit(1, 2, 3, 4, 5, 6, 7, 8)
	out := make(chan int)

	var wg sync.WaitGroup

	for range 3 {
		wg.Go(func() {
			for n := range in {
				out <- n * n
			}
		})
	}

	go func() {
		wg.Wait()
		close(out)
	}()

	var squares []int
	for n := range out {
		squares = append(squares, n)
	}

	slices.Sort(squares) // completion order is not defined
	fmt.Println(squares)

	// Output:
	// [1 4 9 16 25 36 49 64]
}
```

## Development

```bash
make test         # vet and race tests
make lint         # golangci-lint
make vuln         # govulncheck
make headers      # add the license header to new Go files
make docs         # copy code from the packages into the markdown pages
make docs-check   # fail when the pages are out of sync
make mutation     # mutation testing: operators (gremlins) and concurrency (tools/mutate)
make docs-serve   # preview the site on http://localhost:8000 (needs Docker)
make check        # everything CI runs
```

The linters are pinned in `tools.mod`. The code blocks in the documentation are generated by `tools/docsync`.
See [the contributing page](docs/contributing.md) for how to add a pattern.
